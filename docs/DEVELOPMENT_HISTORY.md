# 方法迭代留痕

本文把历史实验压缩为当前实现所需的决策链，原始大体量 PDF、JSONL 和旧版说明不再作为仓库文档。实验数字保留原口径，不能混称为当前 50k 最终质量。

## 1. 数据与 mask 语义

早期版本从一张图挑少量 mask，容易把源数据质量、指令指代和目标图质量混在一起。当前改为每个有效 mask 独立规划；保留原始 mask，不因面积、遮挡或审美筛源。`ref/point/box/mask` 只改变定位载体，必须指向同一 selector。对花瓣、按钮、窗扇等重复实例，规划 prompt 要求颜色、相对位置、宿主和部件层级组合消歧。

## 2. 指令协议

历史 instruction 曾包含长段位置补充、保护条件和生成要求，既冗余又增加模型错配。当前收敛为单句动词开头的协议：操作 + 精确目标 + 必要属性/关系。保护项进入结构化 `instruction_spec` 和编辑 prompt。四类语义固定，add 首选新增物体直接附着/所在的 mask 宿主，只有覆盖宿主不自然时才使用近邻锚点。

## 3. 规划模型和输入

早期多轮复核、挑目标和整图多 mask 输入造成调用多、速度慢且仍会错指。当前每个 mask 一次规划调用，输入为全景图、显著标注的局部 crop 和结构化几何信息；采用两个 TP=4 副本，并通过类别缺额指定优先操作。规划结果必须给出 `operation/ref/scope/payload/attributes/placement` 或明确拒绝，不能静默回退到另一类。

## 4. 类型平衡

历史候选在 attribute 上长期偏多，单纯把计划后的数量重采样会丢失 mask 覆盖，也会把不适合 remove 的对象硬改。当前在 wave 前计算剩余类别缺额和观察到的生图通过率，规划阶段指定类型，审核通过后才占用配额；每类不足继续从新源图补充。最终合并再次验证四类严格相等。

## 5. 生成和审核

早期生成器逐条启动、审核串行，冷启动和队列等待占据主要时间。当前每 rank 常驻 6 个 Qwen-Image-2.1/vLLM-Omni 编辑器和 2 个 Qwen3.8-27B 审核器；本地 SQLite 队列负责租约、恢复、批量审核和生成到审核的实时交接。40 steps、seed 0 和区域保护保持不变，避免用降低步数换吞吐。

历史 30 图/60 case 完整质量验证：规划目视通过 52/60，目标图目视通过 46/60，自动审核通过 52/60，三者交集 40/60。典型问题是 Ref 与 mask 错配、add 未真正附着、attribute 边缘混入源色、replace 层级不对、remove 对不适合部件的误用，以及自动审核漏检/误拒。该结果支持“自动审核用于分流、人工验收用于发布”，不支持自动审核直接替代人工。

## 6. 加速实验

审核从单条 Transformers 改为 vLLM batch 8；60 条重放中判定与原基线一致，审核 work 由 704.01 秒降到 153.02 秒。生成和审核采用 6+2 worker 后，60 条小批量墙钟约 293 秒，约 737 原始例/小时；这是小批量工程吞吐，不含规划、冷启动和人工验收。

规划图像缓存、批量提交、共享队列和候选池复用都已落地。实验表明冷启动/JIT 对首批影响很大，热态 planning batch 约 67–75 秒；当前正式运行单独记录冷、热阶段，避免把短批次数字外推为长期 SLA。

## 7. 源数据和部署可靠性

一次四机任务曾因依赖准备机的 SG2 FUSE 路径而在启动前失败。修复方式不是删除检查，而是将本轮冻结的原始 TFRecord 记录缓存到共享目录，启动校验 cache manifest、CRC 和 hash，四机只依赖共享盘。随后又发现 CUDA 12.9 机器安装未限定 vLLM wheel，编辑环境误选 CUDA 13 并报 `libcudart.so.13`；当前 lock 明确指定 cu129 wheel，`uv pip sync` 清理多余包，ready 前执行真实 GPU 检查。

2026-10-14 的后续启动故障有两个直接原因：audit 环境 GUI/headless OpenCV 同装导致子进程缺少 `libxcb.so.1`；共享盘并发加载编辑器权重超过 Omni 默认 600 秒。修复只保留 headless 并增加 spawn 检查，在节点本地校验缓存编辑和审核权重，初始化超时放宽至 1800 秒。补丁发布持有四机锁、备份旧部署并核验 planner 快照，保留原 root、指令、配额和所有检查点。此前仅后台日志定时写入，未实现聊天推送，监控说明已纠正。

## 8. 当前取舍

当前最优版本优先保证四件事：mask 与 Ref 一致、类型配额可控、失败可恢复、源记录可复现。它仍保留自动审核误判和生成质量波动，因此最终训练集需要人工验收；任何新增 instruction、mask 语义或模型后端变更，都应创建新的运行根目录和新的代码 hash，而不是覆盖正在运行的生产快照。

## 9. 分组数据迭代（2026-10-14—15）

为反事实孪生和紧邻多目标新增独立选择、规划、链式生成和组级审核路径，输入根目录为 `sa1b_samtok_group_inputs_20261014`，与正在运行的 50k 根目录隔离。评测源先预留，再从训练候选中抽取；孪生第一批固定为 5,000 组、评测 200 组，多目标第一批固定为 1,500 组、评测 100 组，选择文件和 RLE 相邻证据持久化后才允许进入规划。

小批验证暴露出两类容易被普通 schema 漏掉的问题：多目标模型可能把 `unit_id` 错配到另一个 object，也可能给两个目标写同一 ref；attribute 还可能生成“把红色 SUV 改成红色”的 no-op。当前 `group_planning.build_multi_group` 强制 `U1…Un` 与 object 顺序一一对应、ref 在组内唯一、generation order 长度和集合严格匹配；`instructions.build_unit` 检查 ref/scope 中的源属性，拒绝重复的颜色、材质、纹理等请求。对应提交为 `45cb1e0` 和 `f8f392f`，全量测试为 237 passed。

多目标初始选择使用固定的 `add/replace/remove/attribute` 序列，受候选自然性约束后出现明显偏斜（训练目标计数为 1,619/1,218/1,042/1,446）。新增 `multi_operation_balance.py`：为每组枚举符合操作合同且通过廉价自然性门槛的序列，再以 MILP 最小化最大四类偏差；无 scipy 时使用确定性贪心回退。已对现有 1,500 个训练组和 100 个评测组原地重排并重新分片，重排只改变合法 `operations`，没有改变 object、邻接证据、source reservation 或目标数配额。全量测试为 244 passed。

审核完整性随后补齐：`group_audit.py` 现在先为每个成员/链式步骤复用 50k 的 operation-aware 27B 单条审核，再执行组级比较；组级 JSON 额外要求 `operations_correct=true`，成员和组级审核均需通过才可进入 `final/`。这避免模型只判断“看起来改了”却把 remove/replace/attribute/add 类型混淆。

Qwen3-VL-8B 规划小批中，修复后 2 组保留 1 组；该组用 Qwen-Image-2.1 在 CUDA 12.9/`TORCH_SDPA` 下完成 4 步链式生成，每步约 16 秒，结构性检查通过。但人工发现其中一个 ref 把 dense 描述明确为黑色的 SUV 写成红色，且改黑属于 no-op，整组按 all-or-nothing 拒绝。当前新增主对象颜色冲突检查、属性 no-op 检查和组内唯一 ref 检查。它仍未经过修复后 prompt 的 Qwen3.8-27B 语义审核和人工签收，因此只作为工程验证，不计入最终交付。Qwen3.8-27B 的 vLLM 0.31.1 cu129 后端已解析 `Qwen3_5ForConditionalGeneration`，首次权重加载约 14.3 分钟；未完成正式审核前不得把 8B 结果标为语义通过。

规划输入复查发现旧全图与 crop 均有半透明彩色填充，黑色 SUV 曾被误认成红色。新版保留干净全图，并在 contact sheet 中逐行并列干净裁图和黑白定位 mask；缓存键加入视图版本、源像素和 mask 内容哈希。孪生构建器同时硬校验预分配操作、直接 add 锚点及评测双成员限定。2026-10-15 的 8 组四类均衡 27B 规划验证正在独立目录运行，完成前不计入交付。

27B 的 8 组初测通过结构校验 2 组、拒绝 6 组，暴露出 payload 整句、target_part 误填和颜色子串误判（red 匹配 obscured）。已补充逐操作字段示例，保留模型核实后的共享 scope，并将 no-op 检查限制到 source_color/ref 的完整词，不读取自由 evidence。当前扩大到 16 组四类均衡验证；生成与审核增加独立阶段清单，以使用各自兼容运行时。评测候选已修正为全部双成员，证据为 `verification/twin_eval_pairs_v2.json`。

16 组均衡 27B 规划在 198.25 秒内完成，16/16 仅表示字段/渲染检查通过，不代表内容质量通过。逐图检查发现石质窗拱被指成蓝色灯带、尾门/侧门被错指、replace 退化为改色，以及 add 位置短语重复。6/16 组真实 mask 面积比超过 3，而 bbox 初筛没有发现；现已在调用规划前、构建组和导出时检查真实面积比，旧缓存也不能绕过导出限制。该批保留为诊断实验，不回写 50k 生产。

分组生成现在保存每组 `generated/<group_id>/group.json`，包含确定性拒绝原因；阶段间通过 `generated.jsonl` 和 `audited.jsonl` 衔接。孪生组级审核改为局部原图/结果/mask 并排比较，防止整图缩小后看不清小目标。复核 PDF 每个成员一页，含原图、结果图和同尺度局部，完整显示五目标链的所有步骤，重建展示包时保留已有复核记录。

上述 16 组已由 assistant 逐一查看源图、局部 mask 和指令：仅 3 组同时通过指代/指令合理性/真实面积比检查；这不是成图最终通过率。定位对照新增实验开关 `--outline-planning-crops`，在原有干净裁图与二值 mask 之外增加第三列外轮廓图，轮廓只画在 mask 外，保留干净照片和目标内部颜色。开关默认关闭；新旧视图用不同缓存摘要，先在同一批候选做回归验证，不将其当作独立泛化测试。
